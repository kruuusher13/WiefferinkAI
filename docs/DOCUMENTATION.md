# GarageAI Documentation

## Project Overview
GarageAI is a voice-enabled AI assistant for the automotive industry, specifically designed to integrate with the **WinCar DMS (Dealer Management System)**. It allows customers to call a garage and perform tasks like checking vehicle status, scheduling appointments, and checking parts stock, all via natural conversation.

## Core Technologies
*   **Voice Interface**: Vapi.ai (Telephony & Speech-to-Text/Text-to-Speech)
*   **Orchestration**: LangChain & LangGraph (State management & Reasoning)
*   **LLM**: Google Gemini 2.5 Flash (via Vapi Custom LLM)
*   **API**: FastAPI (Webhook receiver)
*   **Database**: Microsoft SQL Server (Dockerized)
*   **Tunneling**: Ngrok (Exposing localhost)

## Code Structure

### 1. `main.py` (The Entry Point)
*   **Purpose**: Runs the FastAPI server that acts as the "Brain" for Vapi.
*   **Key Endpoint**: `POST /chat`
*   **Logic**:
    1.  Receives a JSON payload from Vapi containing the user's spoken text.
    2.  Authenticates the request (checking Call ID).
    3.  Passes the user input to the **LangGraph Agent** (`graph.py`).
    4.  **Streaming**: Uses `StreamingResponse` to send the AI's reply back to Vapi word-by-word (SSE format) to minimize latency.
    5.  **Logging**: Logs all interactions to `vapi_requests.log` for debugging.

### 2. `graph.py` (The Brain)
*   **Purpose**: Defines the decision-making logic using a State Graph.
*   **Nodes**:
    *   `agent`: The LLM (Gemini) that decides what to do next.
    *   `tools`: Executes Python functions if the Agent requests them.
*   **Flow**: Start -> Agent -> (decides Tool?) -> Tool -> Agent -> End.
*   **System Prompt**: Defined here. It governs the AI's personality ("Speak English", "Be concise") and access rules.

### 3. `tools.py` (The Hands)
*   **Purpose**: A collection of functions that the AI can "call".
*   **Database Connection**: Uses `pyodbc` to connect to the SQL Server container.
*   **Key Tools**:
    *   `identify_customer(phone)`: SELECT query to find customer name.
    *   `check_werkorder_status(plate)`: JOIN query to find repair status.
    *   `schedule_appointment(date)`: INSERT query to create a new work order.

### 4. `docker-compose.yml`
*   **Purpose**: Spins up the local SQL Server instance.
*   **Service**: `wincar_sql` (Azure SQL Edge).
*   **Creds**: `sa` / `StrongPassword123!`

## How to Visualize Processes (LangSmith)

LangSmith is critical for debugging complex AI chains. It shows you exactly what the LLM generated and how tools were called.

### Setup
1.  **Get API Key**: Sign up at [Smith.langchain.com](https://smith.langchain.com).
2.  **Enable Tracing**:
    Export these variables in your terminal before running `main.py`:
    ```bash
    export LANGCHAIN_TRACING_V2=true
    export LANGCHAIN_ENDPOINT="https://api.smith.langchain.com"
    export LANGCHAIN_API_KEY="<your-api-key>"
    export LANGCHAIN_PROJECT="GarageAI-Dev"
    ```

### Visualization
1.  Run your agent and make a call.
2.  Go to the LangSmith Dashboard.
3.  Click on the "GarageAI-Dev" project.
4.  **Inspect Traces**:
    *   Click a run to see the "Tree View".
    *   **LLM Call**: See the exact Prompt sent to Gemini and its raw Output.
    *   **Tool Call**: See the SQL query generated by the tool and the raw data returned from the DB.
    *   **Latency**: See how long each step took.
